# WuBuOS gap map — 2026-11-19 (the "load other OSes" directive)

Owner: *"we don't have drivers, we don't have network, we don't have package
management… the idea is our lightweight system loads other operating systems
and their tools, and can load their system — the best OS ever for development,
with AGI integration."* Three parallel evidence audits (driver/network,
package, guest-loading) measured the tree against that directive. Method:
function bodies read, not banners; VERIFIED vs INFERRED marked in the source
audits. This doc is the integrated map + the workflow for the legs.

## The philosophy, restated as engineering

WuBuOS is the **thin sovereign layer**: own firmware, own kernel, own
namespace — and every other OS is a *guest* whose tools become WuBuOS tools.
Two directions, both required:

1. **Down** (bare metal): the kernel must drive real hardware — persistent
   storage, network, USB input, display beyond Bochs — or the sovereign layer
   is a demo.
2. **Across** (guests): loading another OS's binaries/rootfs/tools must be a
   first-class, integrated, agent-reachable operation — not scattered
   half-wired subsystems.

## Reality summary (audited 2026-11-19)

### Bare metal — what the RUNNING kernel actually drives
REAL: APIC/PIT/HPET/RTC interrupts+timers, Bochs-VBE LFB display (live
pixels), PS/2 keyboard+mouse (IRQ-driven), COM1/COM2 serial (IRQ RX),
bus-0 PCI discovery, ACPI/SMBIOS walk, 9P-over-COM2 module fetch+run (A3).
NOT REAL: **storage is an 8 MB RAM disk wearing an AHCI costume** (ahci.c
sim_disk memcpy; zero persistence across reboot); NVMe probe-only (test-hook
MMIO, ASQ/ACQ programmed to 0); **no NIC driver, no TCP/IP anywhere in the
kernel**; USB = partial xHCI bring-up, no completions/enumeration/transfers
(USB-only machines have NO input); no audio (hda_probe fabricates codec
answers); no GPU driver (Bochs only; GOP fb parsed but never mapped).
The ~150 "driver" modules are perception/routing tables for a Linux host or
test-injected register models. Firmware HAS real e1000/xHCI/AHCI/NVMe boot
drivers — they die at kernel_main. WuBuKernel (driver model + PMM) is proven
by test_kernel_bridge but NOT in KERNEL_OBJS.
**Cross-cutting prerequisite:** wire `dev->bar0 → wubu_vmm_map_page → probe`
(the LFB mapping in metal_main.c proves the mechanism; the registry already
carries BARs; nothing connects them).

### Package management — two disconnected stacks, no trust, no entry
A: runtime registry (wubu_pkg.c) — real resolve/version semantics, install is
STATE-ONLY (flips an enum). B: hosted SQLite pkgmgr — real .wubu
create/extract/install + real repo-index HTTP fetch, but **no payload
download** (download_url/sha256 parsed then discarded), **verification is
theater** (magic-only; FNV placeholder "signature"; CRC never checked),
**files table never populated** (verify_installed vacuous), **install_path
mismatch** (remove deletes an empty dir, leaves payload), upgrade uses
strcmp, txn rollback always-false (honest stub). TLS compile-gated OFF +
silent https→http downgrade (trust bug). C: Arch leg — REAL host
pacstrap/pacman/chroot via archd socket (the only working other-OS-tools path
today, hosted-Linux-only). AUR client + PKGBUILD parser real but unwired; OCI
blob fetch binary-UNSAFE (strlen) with zero callers; no .deb/brew/MSI.
**No pkg CLI, no pkgmgr GUI app, /n/pkg never published in production.**

### Guest loading — two exec worlds, mostly disconnected
Hosted product's "VSL" = fork+exec HOST delegation (real); the in-process
5-personality VSL stack (~60 files, real syscall ABI lab) is linked ONLY into
tests — `nm src/hosted/wubu | grep -c 'T vsl_'` = 0. Loaders (ELF/Mach-O)
prove parse+map but NOTHING transfers control. Bare-metal PE execution is
REAL and proven (zx pipeline, IAT snap, A3/A4 9P fetch+run, entry=42/43/55
gates) — but Win32 DLL personality tables are NULL-handler stubs.
Proven hosted: Linux ELF via container (marker gate), Win32 PE via Wine
(marker gate), DOS in-process 8086 (in make test), Arch bootstrap/import/
service supervision. Broken/missing: **desktop PE launch** (NULL prefix,
exe path dropped), **proton/proton2 symbol collision** masked by
--allow-multiple-definition (proton2 dead in product), **per-container 9P
written but skipped** (containers have no namespace), no unified guest
manager / /n/guests, session switch records a command string but never
executes it, no generic rootfs import→launch UX, no full-OS image boot,
no agent tool-execution surface.

## Prioritized legs (each: smallest real increment + behavior gate)

### Wave 1 — in flight (parallel worktree agents, 2026-11-19)
- **L1 virtio-blk: real persistent storage.** Split-vring driver on PCI
  1AF4:1001, BAR mapped via vmm, attach through fat32_blk_ops REPLACING the
  sim disk (sim stays fallback). Gate: QEMU -drive; write file → reboot →
  read back (impossible today). Template: fw_ahci/fw_nvme register discipline.
- **L2 pkgmgr: download + sha256 + bookkeeping.** download_url/sha256 into
  schema; real payload fetch into cache; sha256 gate before extract; files
  table populated at install; install_path = true layout root; remove
  deletes payload. Gate: local HTTP fixture serves index + .wubu; install
  from download; tamper rejected; remove verified on disk.
- **L3 desktop PE fix + proton collision.** hosted_pe_executor passes the
  exe path + resolves/creates default prefix; proton2 symbols renamed
  (owner per concern); drop --allow-multiple-definition reliance;
  test_era_apps/test_exec_games into a real tier. Gate: era marker pattern
  through the DESKTOP executor, not just wubu_exec_win_pe.

### Wave 2 — bare-metal reach
- **L4 GOP framebuffer fallback** (cheapest display win): when Bochs absent,
  map the Limine/GOP fb (address/pitch/bpp already parsed) via vmm +
  vbe_set_render_target → real-hardware display, zero new driver.
- **L5 virtio-net + minimal IP/UDP/ICMP** (static IP first): one RX+TX
  vring, ARP+ICMP echo+UDP; socket-lite API so 9P can run over UDP instead
  of COM2. Gate: QEMU user-netdev, ping/UDP round-trip in serial.
- **L6 xHCI HID completions**: event-ring processing, Address Device, one
  interrupt-IN endpoint → wubu_hid sink (same as PS/2). Gate: qemu-xhci +
  usb-kbd keypress echo. USB-only machines get input.
- **L7 CI boot-fault bisection** (gate prerequisite): QEMU 10.2.1 runner
  triple-faults at 303 bytes (post-heap-init) where local 8.2.2 boots;
  machine-type/CPU variant matrix + -d int exception log to find the vector.

### Wave 3 — the "load their system" UX
- **L13 WEMU integration** (repo LIVE: github.com/waefrebeorn/wemu, e1a6601):
  clean-room C11 x86-64 emulator backbone — interpreter (integer core +
  SSE2/AVX2 seed incl. the founding vmovd/vpbroadcastb), 4-level paging,
  COM1 machine, syscall hook; all four gates green (400 differential ISA
  cases + the CI memset vector body vs native memset). Next: consume as
  WuBuOS submodule; ISA completion → JIT via WuBuNOS encoder → VT-x VMM →
  virtio devices → guest manager boots Linux through it on bare metal.
- **L8 rootfs import→launch**: any distro tarball (wubu_rd_load already
  imports) → register root → launch shell; OCI layers→rootfs assembly
  (binary-safe blob rewrite first). Desktop "Guests" entry.
- **L9 per-container 9P + /n/guests**: run the written-but-skipped Styx
  server per container; guests/{list,state,launch} via ns_bridge; unified
  guest API over archd/proton2/ramdisk slices.
- **L10 pkg entry points**: `pkg` command + publish /n/pkg in the live
  bridge; AUR→.wubu bridge (parser+client exist, wire them); real signatures
  + TLS with CA checking; kill the https→http downgrade.
- **L11 VSL execution engine or honest demotion**: enter a loaded static ELF
  entry with a syscall trampoline into vsl_syscall_dispatch (gate: no-syscall
  ELF returns 42; then one write-syscall program) — or formally label VSL an
  ABI lab and route product exec through containers. No third option.
- **L12 on-metal Win32 import substance**: modsym-backed msvcrt/kernel32
  console subset (printf/exit/GetStdHandle/WriteFile) as kernel exports;
  gate: PE importing those names, A3 export-flips-result pattern.

### Hygiene (cheap, fold into adjacent legs)
- wubu_exec.c:443 pointer-as-int64 return (DOS branch).
- secmon attach reads parent env not ct->envp; no ptrace pump in ct_wait
  (stop-deadlock hazard).
- wubu_exec_dos banner claims FreeDOS (body: in-process shim); proton2
  banner claims pacstrap install (body: none) — banners must match bodies.
- SQL injection surface in pkgmgr (snprintf of network strings).

## Workflow rules for every agent on these legs

1. **Worktree per leg** (`git worktree add`), own branch, commit locally;
   the integrator merges sequentially. Never two agents in one tree.
2. **Behavior gate or it didn't happen**: every leg extends/creates a test
   that asserts REAL output (marker files, return values, round-trips,
   on-disk state) — non-crash is not a gate. QEMU serial asserts for metal.
3. **No theater**: a success-path no-op is a bug, not a stub to preserve.
   Error-path guards are fine. Banners must match bodies.
4. **One owner per concern**: search before writing; reuse wubu_sha256,
   pkg_version_cmp, the vmm mapper, the fat32 blk_ops contract, modsym.
5. **Verify by running**: make <target> + read real output; metal legs boot
   under QEMU locally (8.2.2) AND keep ci_boot_assert green; gcc14-class
   strict stays clean (make kernel-strict for kernel touches).
6. **Docs are testable**: new paths named in docs must exist (test_docs).
7. Submodules untouched unless the leg IS the submodule (WuBuKernel public).

### Audit round 10 (2026-11-20, DISPROVED hypothesis - no code shipped)
- Hypothesis: the WEMU bridge's ioctl case bounces a fixed 256 bytes in
  AND out, so a small request (TIOCGWINSZ=8, TCGETS=60) would overwrite
  guest bytes next to the struct. A canary guest probe was built and
  run through the real bridge with both requests.
- **Negative control disproved it**: the probe passed unchanged against
  HEAD's old 256-byte bounce. The bounce is read-modify-write — gread
  preloads the guest bytes into the host buffer, so bytes the ioctl does
  not touch are copied back intact. Guest ioctls are also bounded to a
  host scratch buffer, never a raw guest pointer. No clobber, no
  fail-open: the speculative request-aware rewrite and its gate were
  REVERTED; the busybox gate is green on the original code.
- Lesson: a gate that passes with and without the fix is not a gate.
  Build the negative control BEFORE claiming the defect.
### Audit round 11 (2026-11-20, TLS trust leg)
- **The TLS enable macro collided with mbedTLS's own include guard**:
  `MBEDTLS_SSL_H` was both the project's "enable TLS" flag and the guard
  inside `mbedtls/ssl.h`. Defining it made `ssl.h` skip its contents; the
  path was effectively dead. Renamed the feature flag to
  `WUBU_HAVE_MBEDTLS` in `oci_internal.h` / `oci_http_client.c`.
- **Explicit CA verification**: the old code called VERIFY_NONE *before*
  `mbedtls_ssl_config_defaults`, which resets the config. Negative control
  showed the old path actually failed BOTH untrusted and trusted handshakes
  (the "insecure VERIFY_NONE" comment was wrong — it failed closed by
  accident). Now a CA bundle is loaded from `WUBU_CA_BUNDLE` or
  `/etc/ssl/certs/ca-certificates.crt`, VERIFY_REQUIRED is applied AFTER
  defaults, and `mbedtls_ssl_get_verify_result` is checked post-handshake:
  untrusted/missing CA fails, trusted CA succeeds.
- Gate: opt-in `make test_oci_tls` (needs `WUBU_MBEDTLS_ROOT`; not in the
  default tier because CI has no mbedTLS dev package). Real local mbedTLS
  2.28 server + self-signed cert: no-CA connect <0, trusted-CA connect 0;
  negative control with HEAD's client fails both. `test_oci` 10/10 and
  the default non-TLS build still compile and pass.

## Devil's advocate — what we missed, recursively (2026-11-19, research + probes)

Owner directive: attack our own work with online research + ingenuity.
Findings, each with the evidence and the leg it spawns:

1. **We built the harder emulation path first.** FEX-Emu, box64, and
   qemu-user are USER-mode emulators: translate CPU + syscalls, pass
   everything else to the host — that is how "load their tools" works in
   the real world (fex-emu.com; FEX FOSDEM 2022; qemu-user docs). WEMU's
   skeleton is full-system-flavored (paging/COM1). The fast path is a
   **WEMU user-mode leg whose syscall hook dispatches into the VSL Linux
   table** — two islands become one stack, our own FEX. → **L14**.
2. **Our gates were below the industry smoke test.** The QEMU project's
   own testing guidance: "Smoke testing tip: use static busybox", LTP for
   syscall coverage (wiki.qemu.org/Testing; linux-user slides). Hand-
   assembled return-42 ELFs prove mechanism, not mission. Acceptance gate
   for L11/L14: **real static busybox applets** (echo/ls/cat/uname) run
   through the engine with correct output. → folded into **L14/L18**.
3. **Static-only is not "their tools".** Real binaries are dynamic:
   qemu-user needs the guest ld.so + libs (QEMU_LD_PREFIX; qemu-user
   docs). VSL engine maps static segments only. → **L15**: load the guest
   ELF interpreter + libraries from an imported rootfs (ties to L8).
4. **The VSL engine is not a sandbox.** Its seccomp filter traps syscalls
   only INSIDE the guest IP window (skill wubuos-vsl-exec-engine); guest
   code executes natively and can jump OUTSIDE the window where syscalls
   are ALLOWED — a malicious guest reaches host code. WEMU interpretation
   is the true sandbox (guest bytes never execute natively). → **L17**:
   route untrusted guests through WEMU; keep native VSL for trusted ones.
5. **Transparent launch is missing.** Fedora Asahi ships muvm + FEX +
   binfmt_misc so foreign binaries "just run" (docs.fedoraproject.org
   asahi x86-support). We have no binfmt registration (hosted) or
   registry routing (bare metal). → **L16**.
6. **The march bug class had a second home.** Firmware build.sh inherited
   distro march too; -mno-sse already blocked vector codegen (verified:
   0 vector opcodes in wubufw.elf), but the pin is now explicit
   (-march=x86-64) against future flag drift. Kernel link line audited:
   objects compile with pinned KERNEL_CFLAGS ✓. Class closed.
7. **WEMU's own gaps, found by expanding the differential gate** (the
   first gate covered 6 ops × 2 widths — survivorship bias): CLC/STC
   were missing (every carry chain faulted); CPUID had EBX/ECX swapped
   and claimed no features (guests would never emit the AVX2 we
   implement); vzeroupper/xgetbv absent (the AVX enablement chain);
   rep movs/stos absent (real memset/memcpy). ALL FIXED + gated: 800
   differential cases (8 ops × 4 widths × CF, flags checked), string ops
   vs native libc, CPUID-claims-what-it-executes. Remaining honest gaps:
   x87, LOCK/atomics, SSE4/AVX beyond the seed, real exception delivery,
   self-modifying-code invalidation (matters once JIT lands). → **L19**.
8. **Syscall coverage needs a gauntlet, not anecdotes.** LTP under the
   engine (QEMU's own unit-test approach) → **L18**.

### New legs
- **L14 WEMU user-mode + VSL bridge**: flat-memory exec mode, syscall
  hook → vsl_syscall_dispatch; acceptance = static busybox applets with

- **L15 guest dynamic linking**: ld.so + lib resolution from imported

- **L19 WEMU ISA completion**: x87, LOCK/atomics, SSE4/AVX growth,
