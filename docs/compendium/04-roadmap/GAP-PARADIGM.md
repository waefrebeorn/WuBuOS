## The paradigm rules (the planning strategy)

1. **Bottom-up close order.** P0 → P1 → P2 → P3 → P4 → P5. The OS must BE
   before the user space rides it; the Colonel must exist before the AGI
   lives in it. The metal (P0) and the Colonel core (P3) are the load-bearing
   planes — gaps there close before cosmetic gaps anywhere.
2. **The cross-plane gap closes FIRST.** A gap that bridges two planes (the
   Colonel-dispatch GU-H55-58, the AGI-GUI GU-G, the verifier→EDR SC-E, the
   synthesis→GUI WT-G) is worth more than any single-plane gap: it is the
   integration. The close-priority = (plane-count the gap touches) × (plane
   depth, P0 highest).
3. **The wave-plan (the cron cadence).** Each KB-growth-research tick does
   BOTH: (a) closes the highest-priority open gaps in the current plane
   batch (a real C11 module + test + the bank-flips, per the M1/M2
   meta-plan), AND (b) grows ONE new avenue in the next plane. Growth and
   closure stay in balance — the backlog never runs away (M2).
4. **The avenue plan (the 25K path, plane-assigned).** The remaining
   avenues fill their planes:
   - P3 first (the Colonel space is the AGI's home): **DevTools** (the
     Colonel IDE, the debugger, the LSP), then the compiler/PTX banks.
   - P5 (the senses): **Media**, **Games**.
   - P1 (the services): **Cloud**, **Comms**, **Energy**, **Privacy**.
   - P2 (the user space): **Web**, **Accessibility**, **Education**,
     **Community**.
   - P4 (the brain): **Science**, **Math**, **Robotics**.
   - P0 (the metal): **IoT**, **Mobility**.
5. **The paradigm ledger.** Every bank-row and every plane-row is counted
   by the paradigm-map generator (tools/gen_paradigm_map.py) so the "know
   where we are by knowing where we aren't" is a NUMBER per plane, not a
   feeling. The map regenerates on every commit.
6. **The doctrine holds.** No fabricated gaps; DA after every batch; the
   ledger-flip in the same commit; the sibling-collision protocol; the
   honest-open for the external-resource gaps (AX02/03, CC08).

The user's directive: "research as many avenues as you need" — the
paradigm answers "which ones first": the avenue-order follows the plane
depth (P0/P1/P3 first), and every avenue downloads its sources into
