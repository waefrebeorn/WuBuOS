# Ed25519 verification policy without mbedTLS

## Purpose

Ship the native OpenSSL Ed25519 backend in hosted/product builds even when no
mbedTLS dev root is installed. The two verification rules that must never be
delegated to a primitive — canonical `S` and cofactor-small public keys — are
implemented with fixed-width byte comparisons in `src/runtime/wubu_eddsa_policy.c`.
No bignum library and no third-party code is used.

## What is checked, and why

RFC 8032 verification is `[S]B == R + [k]A`. Two extra rules make it secure:

1. **Canonical `S`.** The high 32 bytes of the signature encode `S` as a
   256-bit little-endian integer. It must be `0 <= S < L`, where
   `L = 2^252 + 27742317777372353535851937790883648493`. `S == L` and larger
   values are malleable. The check is a byte loop from the most significant
   byte down; no 256-bit integer type is needed.

2. **Small-subgroup `A`.** Ed25519 has cofactor `k = 8`. If `A` has order 1, 2,
   4 or 8, then `[S]B == R` holds for arbitrary `S` and an attacker forges a
   signature without the secret key. The old mbedTLS path detected this by
   computing `[8]A` with bignums and comparing to the identity. The
   bignum-free layer instead compares the 32-byte compressed key against the
   complete, finite set of encodings that decode into the order-8 subgroup.
   That subgroup has exactly eight points, so the table is a proof, not a
   heuristic denylist. Both sign bits are listed because negation of a
   small-order point is also small-order, and the OpenSSL decoder accepts the
   non-canonical `y = 1` / `y = p - 1` sign bit. Encodings with `y >= p` are
   refused by a fixed-width compare against `p = 2^255 - 19`, matching the
   mbedTLS ladder's `ge_frombytes()` rejection.

Both checks run before the OpenSSL primitive is called. If the primitive is
unavailable, sign/verify fail closed with an error; they never return a
success value from a policy-only path.

## Backend matrix

`tools/detect_native_eddsa.sh` probes only installed software; it never
fetches anything.

| OpenSSL 3 | mbedTLS dev root | shipped backend | policy implementation |
|---|---|---|---|
| yes | yes | native + ladder fallback | mbedTLS bignum (unchanged), native path guarded by it |
| yes | no | native only | `src/runtime/wubu_eddsa_policy.c` |
| no | yes | ladder only | mbedTLS bignum (unchanged) |
| no | no | fail closed | none; public entry points refuse |

The generated `build/native_eddsa.mk` and `build/native_eddsa_config.h` carry
`WUBU_EDDSA_CFG_NATIVE`, `WUBU_EDDSA_CFG_LADDER`, `WUBU_EDDSA_CFG_POLICY` and
the matching `WUBU_HAVE_*` macros. The invariant is now "any backend implies a
policy", not "native implies mbedTLS".

## Gates

- `test_eddsa_build_config` (`tools/eddsa_config_gate.sh`) proves the detector
  matches an independent probe, enables native with no dev root, emits no
  mbedTLS macro or `-lmbedcrypto` in that state, and invokes no network fetch.
- `test_eddsa_nombedtls` (`tools/eddsa_nombedtls_gate.sh`) compiles the real
  signing leaf with `--force-mbedtls=0`, signs/verifies with an ephemeral
  OpenSSL key, and refuses tampered signatures, wrong keys, tampered digests,
  non-canonical `S`, every small-subgroup encoding class and non-canonical
  `y`. When a dev root is supplied via `WUBU_DIFF_MBEDTLS_ROOT`, it builds the
  same entry points the mbedTLS way and asserts identical accept/reject
  classes for every vector plus cross-build signature interchange.
- `test_eddsa_runtime` runs the above plus the existing native/ladder/fallback
  differential.

No key material is written into the repository; all keys are generated by the
OpenSSL CLI into a temporary directory removed on exit.
